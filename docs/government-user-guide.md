# 国・政府組織グループの使い方

国の正本と政府組織の正本を、別々のプロジェクトとして管理します。政府組織は、接続した国グループに登録されている国のIRIを参照します。同名でもIRIが違えば別の国・組織です。名称やコードを変更してもIRIは変わりません。

組織の構造・改編には [W3C Organization Ontology](https://www.w3.org/TR/vocab-org/) の語彙を使用し、国所属・日単位の期間・名称履歴などはアプリの拡張語彙で記録します。人員配置や個人の所属を入力する組織図のテンプレートではありません。

## 最初の登録

1. Homeの「国」を選び、「国グループを作成」を押します。既存のプロジェクト作成ダイアログで、名称・基底IRI・主言語を指定します。実在国のデータは自動投入しません。
2. 「国を登録」から正式名称・言語を入力します。必要に応じて多言語名称、別名、任意コード、説明、出典を追加します。コードは任意の識別値で、ISOコードであることを保証する機能ではありません。
3. Homeの「政府組織」から政府組織グループを作成します。「国グループ」で参照元を選び、変更内容を確認して接続を適用します。
4. 「政府組織を登録」から名称・言語・種別・国・存在期間・国所属の期間・出典を入力します。国候補は名称・別名・コード・IRIで検索し、次ページも選択できます。同名の候補はコードとIRIで区別します。

国・政府組織の入口はmanifest情報だけを読みます。閲覧者もグループを開けますが、作成・変更には編集者または管理者の権限が必要です。専用画面から「モデル編集」に切り替えると、通常のRDF編集も利用できます。

## 期間の意味

開始と終了には、それぞれ次の三つの状態があります。

| 入力 | 意味 |
| --- | --- |
| 日付不明 | 境界が分かっていない。無期限とは扱わない |
| 期間の境界なし | その側の境界を設けないことを明示する |
| 日付を指定 | 日単位の境界。開始日は含み、終了日は含まない |

例えば終了日が2020-04-01の関係は2020-03-31まで有効で、2020-04-01には無効です。同日を新しい関係の開始日にすると、切り替わりが連続します。日付が不明の関係は別の一覧に残り、現在の事実と断定しません。基準日に確定した所属国がない場合は、その状態を表示します。過去の国所属を現在の所属として補完しません。

組織の存在期間、関係の有効期間、名称の有効期間は別々です。存在期間が不明でも、関係の期間だけを確定できる場合があります。存在期間外の組織に接続する関係は確認事項として表示し、基準日の投影から除外します。期間外の組織は、表示切替で確認できます。

## 組織・部署の関係

「関係を追加」では、主体となる組織から相手への向きを指定します。

| 選択 | 記録する関係 |
| --- | --- |
| 国に所属する | 組織 → 接続先国グループの国 |
| 部署として所属する | 部署 → 上位組織（`org:unitOf`） |
| 下位組織として所属する | 下位組織 → 上位組織（`org:subOrganizationOf`） |
| 監督を受ける | 被監督組織 → 監督組織 |
| 連携する | 組織間の対称的な関係 |

組織間の端点は同じ政府組織グループから選びます。異なる国に所属する組織の関係も記録できますが、国をまたぐ包含は警告します。監督・連携は包含階層とは分けて扱います。

確定した期間が重なる包含循環や、同じ時点の複数国所属・重複関係は拒否します。日付不明のため重複する可能性がある場合は警告します。確認画面で期間と出典を見直してください。

## 移管・統合・分割・改称

「改編を追加」で、種類・施行日・変更前と変更後の組織を選びます。統合は前身2以上・後身1以上、分割は前身1以上・後身2以上を指定し、前後が同一の組織集合になる指定はできません。「その他」では説明も必須です。前身・後身は複数選択できます。新設組織は先に登録してください。改編イベントから未登録組織を暗黙に作成しません。

移管・改称では変更前後に同じIRIを選びます。吸収統合では、存続する組織のIRIを変更後に残せます。改編の種類や施行日だけでは、元の組織の存在期間・関係・名称を自動変更しません。

部署移管の例は次の手順です。

1. 関係の変更を追加し、「既存記録」から旧上位組織への関係を読み込みます。
2. 旧関係の終了日を移管日にします。
3. 関係の変更をもう一つ追加し、同じ部署から新上位組織への関係を作ります。開始日は移管日にします。
4. それぞれの出典を入力し、変更内容を確認して適用します。

必要な場合だけ、名称履歴・存在期間の変更も同じ改編へ追加します。吸収される組織を終了させる場合も、存在期間の終了を明示してください。未来の名称は名称履歴として登録でき、基準日が到来する前の表示名を上書きしません。その日の表示言語で一意に確定した名称履歴がない場合は、通常の名称に「名称の時点未確認」を添えます。辞書の表示言語とUIの言語は独立して選べます。

確認画面には追加・削除される全ステートメントをページ分けして表示します。確認後にチェックを入れて適用すると、一つのcommandとして確定し、Undoも一回です。入力・参照元・対象文書が変更された場合は、古いプレビューをそのまま確定できません。

履歴の一覧や既存記録の選択では、記録のIRI・名称・説明・出典などを検索できます。未来の名称を検索しても、基準日前の組織名をその未来の名称に置き換えません。

既存の改編イベントの説明などを編集する場合、関連記録は保持します。関係・名称・存在期間も変える場合は、変更する記録を明示して追加してください。

## 参照元の変更・競合

国名の変更は政府組織の表示にも反映され、参照IRIは保持します。国の削除や参照元の未接続を、組織の連鎖削除として扱いません。未解決のIRIを表示します。

国グループの切替では、既存の参照が解決できるかを先に確認します。名称が同じという理由で別IRIへ置き換えません。

選択後に国情報が更新された場合は確定を拒否し、入力を保持します。組織登録では国候補を再確認し、同じ国でも明示的に選択し直してください。履歴フォームでは「国の参照元を再確認」後、変更内容を再度確認します。国そのものの編集で再読込する場合は、入力を破棄する前に確認します。

別画面へ移動するときの未確定入力は、破棄を確認します。チーム再認証でも入力を保持し、以前の確認済みプレビューは再利用しません。未対応のRDFを含む記録は専用フォームから書き直さず、通常のモデル編集で確認できます。

## 保存・複製・バックアップ・出力

ローカルでは通常の保存操作を使います。未保存の受理済み履歴も、専用グループの全履歴ZIPと複製に含めます。保存前のファイルは`.semantic-studio-originals*`以下に残し、元プロジェクトを保存・変更しません。通常の既存ローカルプロジェクトのZIP動作は変更しません。

チームでは受理済みRDF・metadata・監査・再送情報をPostgreSQLの正本へ保存します。既存の本人Undo・競合検査を維持します。自分が後から別の変更を確定している場合など、以前の操作を対象にしたUndoが拒否されることがあります。

「全履歴をダウンロード」はプロジェクトZIPです。国の参照元グループを自動同梱しないため、別環境へ移す場合は必要な国グループも保持してください。参照元project IDが存在しない復元では未接続の状態とIRIを保持し、明示的に再接続します。チーム全体のバックアップ・復元手順は[運用ガイド](p2-team-operations.md)に従います。

「基準日の投影をダウンロード」は、選んだ日付で確定できる関係・名称を投影した派生Turtleです。全履歴の代替ではありません。HTTPヘッダーに基準日と元データのbasisを付けます。

国・政府組織profileは、既存の`dictionary-v1`による公開版のプレビュー・承認には対応しません。明示的なエラーを返し、履歴の一部だけを完全な公開版として承認しません。既存の普通のプロジェクトの公開形式は維持します。

## 入力と表示の上限

候補・履歴は既定50件ずつ、APIの最大ページサイズは100件です。検索は200文字までです。一つの改編の前身・後身はそれぞれ100組織、関係・名称・存在期間の変更はそれぞれ100件まで、command本文は256KiBまでです。日付投影は100,000ステートメントまでで、超過は部分表示ではなく明示拒否します。

複数国への確定した同時所属、国家そのものの分裂・統合、外部の公開国データの直接参照、Excel一括入力、ドラッグによる組織図・タイムラインは今回の専用機能の範囲に含めません。
