# 国・組織マスターのデータ取り込み：改訂設計案

作成・改訂日：2026-11-01（日本時間）。状態：独立レビューの指摘を反映。2026-11-02にユーザーが本設計に基づく現行計画の実装を承認。第1段階実装中。
ユーザーが確定した要件と、実装に向けた設計上の選択を以下で分ける。設計修正の依頼は実装承認とは扱わない。

## 1. 確定した要件と段階

- 取り込み元はすべて対象とする。優先順位は①CSV／Excel、②RDF／Turtle、③Web／PDF。
- 最初のCSV／Excel対応から、新規登録と既存マスターへの差分更新を扱う。
- 国マスター・組織マスターの各タブから取り込む。

第1段階の対象は、国・組織の基本項目、組織の初期期間・所属国、明示的に指定した関係記録の追加・訂正・終了。
統合・分割・移管などの改編イベントや名称履歴の一括生成は第1段階に含めず、既存の専用編集を使う。
後続の入力形式は共通の照合・確認・登録経路へ接続する。RDF／資料抽出の詳細は各段階で設計する。

## 2. 現在の実装から再利用するものと追加するもの

| 既存実装 | 再利用と必要な追加 |
| --- | --- |
| `backend/app/tabular.py` | CSV／Excel解析、上限、XML・ZIP防御。元の行位置・セル種別・識別子の原値は追加で保持する |
| `frontend/src/components/DataWizard.tsx` | ファイル・列対応・プレビューの操作パターン。専用画面はマスター登録用に追加する |
| `backend/app/government/references.py` | 対象グラフ、国参照元、profileと参照基準。検索画面の先頭ページだけで照合しない |
| `backend/app/government/records.py` / `validation.py` | 期間、関係、循環、重複期間の読み取りと検証 |
| `backend/app/editing.py` | Change、文書ロック、Undo、保存境界。一括取り込みの計画・適用を新設する |
| `backend/app/team/workspace.py` とチーム正本境界 | 編集権限、CAS、監査、再送、候補の確定。一括プレビューの明示的な読み取り扱いを追加する |

汎用データ取り込みは別グラフのスナップショットを作るため、その保存経路をマスター更新に流用しない。
国・組織の標準定義と既存profileを使い、個体・関係を `model.ttl` の編集可能なマスターデータとして作る。

**新規の一括取り込みコマンド `ImportMasterBatch` を設ける。**
既存の `CreateCountry` / `CreateGovernmentOrganization` を行ごとに実行しない。
これらは未指定の名称・出典等も置換し、行ごとに履歴を確定するため、部分更新・一括Undo・全件の原子性を満たさない。
既存の検証規則を再利用しつつ、現状と対応付け結果を統合した候補グラフから、1つのChangeを生成する。
APIや型への追加は実装計画で列挙する。既存コマンドの未対応dryRunが、そのまま使えるとは仮定しない。

## 3. 第1段階の操作と表の単位

1. 各マスターの一覧で「データから取り込む」を選び、対象プロジェクトを明示する。
2. ファイル、Excelの場合はシート・見出し行、取り込みモードを選ぶ。1回の取り込みは1つの表を対象とする。
3. 列と項目・言語・値の種別を対応付ける。任意の列名に対応し、モード別の記入例付きテンプレートも用意する。
4. 新規・更新・変更なし・要確認・エラーと、追加・変更・削除される値を元の行位置付きで確認する。
5. 確認した対象行を確定し、適用・変更なし・除外の行数を報告する。

| モード | 1行の意味・照合キー | 主な項目 |
| --- | --- | --- |
| 国の基本情報 | 1国。国コードは表内で一意 | 国コード、言語別の名称、別名、説明、出典 |
| 組織の基本情報 | 1組織。組織コードは表内で一意 | 組織コード、言語別の名称、ORG種別、所属国コード、存在期間・所属期間、出典 |
| 組織の関係 | 1関係記録。1組織が複数行に登場できる | 操作、既存記録IRI、主体コード、関係種別、関係先コード、期間、出典 |

同一組織の複数関係を組織表の重複行で表現しない。上位組織の包含関係も関係表で扱う。
国を先に登録し、組織の所属国は明示的に接続した国マスターで照合する。
関係表は、既に登録した同じ組織マスター内の組織、または接続した国を参照する。
第1段階では、組織の新規登録と包含関係は別の表・別の確定操作とし、複数プロジェクトや複数表を横断する原子的更新は約束しない。

## 4. 行位置と識別コードの忠実性

- CSVは論理レコード番号と、そのレコードが始まる元ファイルの行番号を保持する。空行やセル内改行を考慮する。
- Excelはシート名と物理行番号を保持する。空行や途中の見出し行を読み飛ばした後の配列添字から行番号を推定しない。
- 原列名、列位置、既存parserが付けた重複列名の区別、原値と正規化後の値を保持する。
- 対応付けは列位置で区別し、同じ見出し名を一つに潰さない。利用者の列名はUI上でも文字列として扱う。
- キーの前後空白を除いた値を照合に使い、変更があれば原値と照合値を示す。大文字・小文字、Unicode、国コード体系を自動変換しない。
- Excelのテンプレートではコード列を文字列にする。文字列 `001` は `001` のまま扱う。
- **第1段階ではExcelの数値セル・数式セルを識別コードに使わない。** 表示書式 `000` の数値 `1`、長い数値コード、計算結果のキャッシュからコードを復元・推測しない。該当行に理由を示し、元データを文字列のコードに整えて再読込してもらう。
- 現行parserの文字列化後の値だけでは数値・数式を判別できないため、同じ安全な読取境界でセル型と数式の有無を保持する拡張が必要。既存のXML・ZIP防御を迂回しない。
- 解析メタデータの拡張で、通常のデータスナップショットの既存DTO・読み取り動作・性能予算を破壊しない。

## 5. 個体の照合と部分更新

国コードには既存の `gov:countryCode`、組織コードには `org:identifier` を使う。
これらは既存モデルで一意性が保証されていないため、取り込み側で照合の曖昧さを検査する。
照合範囲は対象マスターの明示された個体と、参照先の国マスター。表示名・検索言語・一覧のページは識別に使わない。

- キーを必須とする。対象で0件なら新規、1件なら更新候補、複数件なら要確認として確定を止める。
- 表内の同一個体キーの重複は行を示して拒否する。初期版は縦持ちの多言語重複行を自動統合しない。
- 既存個体に複数コードや未対応のコード値がある場合、一つを勝手に選ばない。該当する値・個体を要確認として扱う。
- 更新時も既存IRIを維持する。対応付けていない属性、言語、関係、出典、履歴を保持する。
- コード変更やコード未設定の既存項目への更新は、専用フォームでコードを整えてから取り込む。既存IRIを推測しない。
- ファイルに存在しない既存項目を削除・廃止しない。同じ名称だけで同一項目とは判定しない。
- 新規IRIはプレビューと確定で同じものを使う。対象プロジェクトと確認基準に結び付けて生成し、既存ノードとの衝突を検出する。

### 項目ごとの更新規則

| 項目 | 既定の動作 | 明示的な変更 |
| --- | --- | --- |
| 優先名称 | 対応付けた言語の1値を訂正。他言語を保持 | 言語単位の消去を明示する。名称が必須条件を満たさなくなる操作は拒否 |
| 別名 | 対応付けた言語の値を集合に追加。同じRDF値は重複させない | 置換・消去は言語単位で指定し、除去する全値を表示 |
| 出典 | 対象個体・対象記録の集合に追加。他の出典を保持 | 置換・消去は対象を明示し、除去する全値を表示。必須の記録出典を空にする操作は拒否 |
| 説明・ORG種別等の単一値 | 対応付けた非空値のみ訂正 | 消去可能な項目だけ、項目単位の消去を指定できる |
| 未対応付けの項目・空欄 | 更新時は保持 | 空欄を消去として扱う設定は項目・言語・対象を明示し、差分で確認 |

名称の言語は列ごとに明示する。プロジェクト主言語を初期候補にできるが、UI表示言語は書き込み言語にしない。
別名・出典を複数セルから読めるようにし、セル内の区切り文字は指定した場合だけ分割する。
新規行では必須項目を検証する。共通値は、元データにない値として確認画面で明示的に指定する。
既存行では欠けた期間・出典を新たな共通値で埋め直さず、既存値を保持する。
優先名称の訂正から名称履歴・改称イベントを自動生成しない。

## 6. 期間・関係記録の照合と更新

### 組織表の期間と所属国

新規組織には存在記録と最初の国所属記録を作成する。日付不明と期間の境界なしを区別し、出典を確認する。
既存組織の組織表で期間を訂正する場合は、現行の単一項目フォームと同じ安全な編集範囲に限定する。
既存の存在記録・国所属記録が一意で対応可能な場合のみ、プレビューに記録IRIと「既存記録の訂正」を示し、利用者が選択する。
対応付けていない日付境界・出典は保持する。複数の所属履歴、異なる記録出典、未対応構造がある行は自動で更新せず、専用編集または対象からの除外を求める。
所属国コードの変更は、関係表でどの国所属記録をどう変更するか明示する。組織表の最新値から旧所属の終了日を推測しない。

### 関係表の操作

関係種別は `gov:inCountry`、`org:unitOf`、`org:subOrganizationOf`、`gov:supervisedBy`、`gov:cooperatesWith` の既存の許可範囲。
組織名から種別や包含関係を推測しない。国所属の関係先コードは接続した国マスター、他の関係先コードは対象組織マスターで照合する。

| 操作 | 記録の照合・適用 |
| --- | --- |
| 追加 | 主体IRI・述語・関係先IRI・期間の両境界（日付不明／境界なしを含む）が同じ既存記録を照合。0件なら新規、1件なら記録IRIを保持して出典を集合追加、複数件なら要確認 |
| 訂正 | 既存記録IRIを必須とし、対象マスター・主体・記録種別・対応可否を確認。指定した関係先・期間・出典等だけ訂正する |
| 終了 | 既存記録IRIと明示した終了日を必須とする。終了境界のみを訂正し、その他の値と他の記録を保持する |

すべての行の照合を、変更前の同じグラフS0に対して先に行う。途中行の適用結果で後続行の照合先を変えない。
追加行は、同じ主体・述語・関係先・期間の重複を表内でも拒否する。照合後は、操作種別を問わず、同じ既存記録IRIを複数行が対象にする場合も拒否する。
これは既存記録に一致した「追加」と、その記録の「訂正」「終了」が混在する場合も含む。競合する元の行位置を示し、利用者が1つの操作に整理して再プレビューする。
複数行の組み合わせで同じ最終記録を二重作成・重複期間にする場合も、最終候補全体の検証で拒否する。
変更なしの関係を再取り込みした場合は、新たな記録IRIや重複出典を作らない。
参照先不明や曖昧な既存記録を仮の個体・先頭の記録で置き換えない。
旧関係の終了と新関係の追加が必要な場合は、利用者が両方の行を明示し、同じ候補全体で検証・確定する。
ファイルの最新状態から過去の記録を消したり、終了日や改編イベントを推測して登録しない。

## 7. プレビュー・一括適用・チーム動作

### 読み取りと候補生成

ファイル解析は読み取り処理とし、モデル、Undo、保存状態、チームのリソース版や監査・再送記録を変更しない。
新設・拡張するファイル解析POSTもチームの経路方針に明示登録し、編集権限を要する読み取りとして扱う。未知の経路やファイル解析を正本更新として誤分類しない。
`ImportMasterBatch` のdryRunをローカルとチームの両方で明示的に扱う。チームでは `HISTORY_COMMANDS` に限定された既存の例外をこの専用コマンドへ拡張し、通常の編集権限・認証チェックは維持する。
任意のPOSTや任意コマンドを、dryRunというだけで正本の確定境界から除外しない。

元グラフS0のコピーに、全行の照合・指定値のマージ・関係操作を反映してS1を作る。
S1全体へ既存のprofile・期間・包含循環・重複期間等の検証を適用し、S0とS1の実際の差分を求める。
警告と未解決の要確認を分ける。既存の検証が許す日付不明等の警告は理由と影響を確認できるようにし、確定した期間・関係として表示しない。
clientが任意のRDF差分を渡して書き込むAPIにはしない。サーバーが型のある取り込み操作から候補と差分を生成する。

プレビュー基準には、ファイル内容のダイジェスト、表モード、シート・見出し、列対応・言語・空欄等の設定、対象行、正規化した操作と候補IRI、対象project/document/profile/settingsとグラフの状態、参照国マスターの基準を含める。
表示言語・名前の投影は確認基準を変更しない。基準の生成と確定時の再計算はサーバーが担当する。
利用者が行を除外した場合は全体を再検証・再プレビューする。除外された新規項目や操作に依存する行も再評価する。
エラー・未解決の要確認がある対象行は確定できない。表示だけ「未適用」にして残りを黙って登録しない。

### 確定・失敗・再送

確定直前に、同じ権限・対象・入力・参照基準で候補を再計算し、プレビューとの差異を拒否する。
ローカルは既存の参照共通ゲートと文書ロックを使い、確認後の別編集・Undo/Redo・profileや接続先変更を検出する。
チームは編集用の分離候補を使い、対象と読み取った国マスターの版をCASで確認し、リソース・監査・再送結果を同じ確定境界で記録する。
認証の期限切れ・再認証・利用者変更では、保持した入力を再確認する。古い確定要求を自動送信しない。

S0からS1への差分を1つのChange・1つのUndo単位として適用する。行単位の連続登録はしない。
最後の行の検証失敗、書き込み拒否、チーム競合等で、それ以前の行が部分適用されないことを保証する。
ローカルで候補を公開する処理が失敗した場合も、元グラフ・リビジョン・dirty・Undoを不整合な途中状態にしない。
ローカルの通常保存・自動保存が後から失敗する場合は、既存の未保存状態と回復規則に従って失敗を表示する。ファイルへの保存成功や、既に受理された変更の取り消しを偽って報告しない。
正常な変更には既存の保存・回復・Undo規則を適用する。チームのUndoは既存どおり版付きの逆操作で、競合を拒否する。
全件変更なしならレポートだけを返し、文書リビジョン・dirty・Undoを増やさない。チームでの要求監査・再送結果の扱いは既存の確定規則と整合させる。
確定応答が失われた場合、チームの同じ要求ID・同じ入力の再送は元の受理結果を返す。ローカルの再読込でもキー照合により重複を作らず、新規分を上書きしてしまわないよう再プレビューする。

## 8. 上限と分割

- ファイル5 MiB、表2,000行・100列、セル32,767文字の既存上限を維持する。
- 超過行は先頭だけを無断登録しない。取り込み前に総件数を示し、ファイル分割を案内する。
- **256 KiBは既存コマンドのJSONリクエスト本体の上限**。元ファイルのサイズや生成RDFのサイズとは区別する。
- ファイル読み取り用経路と、正規化した操作を確定するコマンド経路を分ける。プレビュー用コマンドにも同じ要求上限を適用する。
- クライアントとサーバーの両方で、UTF-8に符号化した要求全体のサイズを確認する。上限内でも、候補グラフには既存の履歴編集の100,000ステートメント上限を適用する。
- 2,000行読めても1回で確定できるとは限らない。超過時は対象行を明示的に分割し、各回を再照合・再プレビューする。自動分割・途中までの無確認登録はしない。
- 分割後の各回だけが原子的更新・Undoの単位。先の回で参照先を用意するなど依存順を確認し、複数回全体の原子性は約束しない。

## 9. 後続の入力形式

### 第2段階：RDF／Turtle

既存IRIと標準語彙を尊重して読み、個体・関係・期間付き記録の候補へ変換する。
既存IRIとコードが異なる項目を指す場合は自動統合しない。独自語彙の項目対応と、未対応構造の原記述を示す。
未対応構造は黙って破棄・変換しない。ファイル内の参照からネットワーク取得やowl:importsを自動実行しない。
対応する構造・IRI競合・ソース保存等の詳細は第2段階で確認する。

### 第3段階：Web／PDF

ページ・表・文書から国・組織・関係の候補を抽出し、出典URLまたは資料名・ページ位置を保持する。
抽出候補を利用者が修正・確認した後、共通の照合・登録経路へ渡す。読み取れない識別子・期間・関係は未確定として扱う。
取得には既存のネットワーク承認境界を使用する。OCR、抽出手段、外部サービスの利用有無、原資料の保存方針は第3段階で設計する。

## 10. 第1段階の受け入れ条件と回帰検証

- 国・組織をCSVとExcelから新規登録・部分更新でき、関係表から明示的な追加・訂正・終了ができる。
- 同じ入力の再取り込みで個体・関係記録・出典が重複しない。全件変更なしでは文書版とUndoが増えない。
- 日本語名称1列の更新で他言語を保持し、別名・出典の集合追加で既存値を保持する。明示的な置換・消去では除去値の全体を確認できる。
- 同じ国コードの複数候補、複数コードを持つ個体、重複した入力個体行、同じ組織の複数関係行、曖昧な既存記録をそれぞれ検証する。
- 同じ既存記録への「既存一致の追加＋訂正」「既存一致の追加＋終了」は両方の行順で同じように拒否し、競合行を示す。
- 一つの記録を訂正しても他の記録・出典を保持する。旧関係の終了と新関係の追加を同一候補で検証できる。未対応履歴は明示的に停止する。
- CSVの空行・セル内改行、途中から始まるExcel見出しでも元の位置を示す。重複見出しも列位置で区別する。
- Excelの文字列001、数値1＋表示書式000、数式セル、キャッシュなし数式、長い数値コードを識別し、コードを無断変換しない。
- 最終行での失敗、古いプレビュー、国参照・profile変更、認証変更、権限不足、CAS競合、Undo競合で部分登録しない。
- プレビューがチームの版・監査・再送記録を増やさない。確定応答喪失後の再送で同じ結果を返す。新規IRIは確認時と適用時で一致する。
- 5 MiB・2,000行・100列・セル長・256 KiB要求境界・100,000ステートメント境界と、行除外後の参照・循環を検証する。
- 日本語／英語切り替えで入力・列対応・書き込み言語・確認対象が変わらない。古い読み取り応答は現在のファイル・対象・確認結果を上書きしない。
- Tabで全操作へ到達でき、段階移動時は見出しへフォーカスする。名前・状態・件数を読み上げ可能にし、既存のfocus-visibleを使う。
- 通常のデータスナップショット、専用フォーム、履歴編集、既存Table利用者・性能予算を回帰検証する。
