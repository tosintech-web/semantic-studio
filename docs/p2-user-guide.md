# チーム版の使い方（P2）

運用担当者が明示的にteamモードとHTTPS・Google認証を設定した環境で使います。
ローカル版は引き続き使えます。設定・移行・復旧は[運用手順](p2-team-operations.md)、
検証範囲と本番Googleログインの確認状況は[検証記録](p2-verification.md)を参照してください。

## ログインと言語

「Googleでログイン」から別ウィンドウで認証し、元の画面で「ログイン状態を確認」を選びます。
許可するWorkspaceドメインと初期管理者は運用担当者が設定します。
初めてログインしただけで管理者にはなりません。

UIの日本語・英語はログイン画面でも切り替えられます。UI言語を変えてもメールアドレス、
ユーザーの識別子、IRI、辞書に入力した言語・名前は変わりません。
辞書の表示言語・主言語も、UI言語とは別の設定です。

## 権限と共有保存

| 権限 | できること |
| --- | --- |
| 閲覧者 | 辞書・原文・履歴の閲覧、検索、SELECT、検証・推論、内部用出力 |
| 編集者 | 閲覧者の操作、辞書・Projectの作成、モデル・データ・共有クエリの編集 |
| 管理者 | 編集者の操作、共有資源の削除・復元、メンバーの権限・停止、ネットワーク許可設定 |

アカウント欄で現在の権限を確認できます。管理者は「チームメンバー」で権限と利用停止を
変更できます。最後の有効な管理者を利用停止・降格させることはできません。
画面で無効な操作は、APIへ直接要求しても許可されません。

受理された共有編集は即時にチームへ保存されます。Turtleエディタに入力中の文字は、
適用するまではそのタブだけの未送信入力です。元のTurtleのコメント・書式に関する
書き換え確認と、共有編集の永続保存は区別します。原文をコピー・出力するときも確認してください。
画面を閉じたり「破棄」を選んだりしても、既に受理された他の人の共有編集を消しません。

## 競合したとき

他のメンバーが同じ基準版の後に更新すると、古い版からの要求は拒否されます。
画面は入力を保持し、要求を自動再送しません。別の項目の更新でも共有領域の版が変わるため、
安全のため競合を知らせることがあります。

競合パネルから現在の保存内容を確認します。未送信入力がある場合も、そのフォームを保持した
まま最新の原文を読むことができます。内容を確認した後、表示した版を次の試行の基準として
明示的に採用し、元のフォームへ戻って必要な変更を加え、もう一度適用します。
その間にさらに更新があれば、再び競合として拒否します。

未送信入力がない場合は、定期的な版の確認で表示を更新します。入力中は無言で置き換えません。
確認中に別のProjectや文書へ移った場合、遅れて返った内容を次の対象へ表示しません。

## 履歴・取り消し

アカウント欄の「変更履歴」で、変更者・時刻・操作・版を確認できます。
移行前のデータに架空の個人履歴を作らず、「移行前」として扱います。
技術的な操作名は、必要に応じて詳細を確認してください。

Undoは最新の共有変更が本人の操作の場合に、その逆操作を新しい変更として記録します。
他のメンバーの変更の後には取り消せません。Redoも本人の直前のUndoに限り、
途中で別の変更が入れば拒否します。別の共有項目の更新でも安全のため拒否する場合があります。
履歴とこの判定はアプリの再起動後も維持されます。

## セッションが切れたとき

セッションは最長60分、無操作では30分です。バックグラウンドの状態確認だけでは
無操作期限を延ばしません。失効時は元のフォームを保持して、操作を停止します。
同じアカウントで再認証し「ログイン状態を確認」から戻ってください。
別のアカウントへ、前の人の未送信入力を引き継ぎません。

ログアウト時に未送信入力がある場合は確認します。保持する入力は現在のタブのメモリにあり、
タブを閉じたりページ全体を再読み込みしたりした後まで保存されるものではありません。
既に受理された共有編集は残ります。アプリ内の利用停止は次の要求から反映します。
Workspace側での停止を即時検知する機能ではなく、既存セッションが最長60分残る制約があります。

## 内部用出力

Turtle・Project ZIP・ドキュメントZIPはチーム内部向けです。原本・未公開の情報を
含む場合があり、P3の公開版を作る機能とは異なります。公開する前に内容を確認してください。
秘密・token・本番データや画面画像をGitHubへ追加しないでください。
