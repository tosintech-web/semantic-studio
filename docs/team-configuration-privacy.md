# Google認証の汎用設定と公開範囲

Google Workspace認証は汎用の仕組みとし、導入先の許可ドメインをサーバーの運用設定で指定する。
コード内の固定値・既定値・メールアドレスの末尾で利用資格を決めない。
検証済みID tokenの `hd` が設定値に一致する場合だけ許可し、未設定・空の設定では許可しない。
複数ドメインは `SEMANTIC_STUDIO_ALLOWED_DOMAINS` のカンマ区切りで指定できる。
ソース・試験・公開文書のドメインは予約された例示用の値を使用する。

## 非公開の運用設定

実際の許可ドメイン、公開URL、初期管理者のsub、OAuth client ID/secretは、
導入先のサーバー環境またはsecret管理から供給する。実値をGit、公開文書、
フロントのビルド変数、ログ、スクリーンショットに埋め込まない。
公開client IDと秘密のclient secretは性質が異なるが、実運用の設定一式は公開サンプルにしない。
公開テンプレートは [.env.example](../.env.example) の空欄・placeholderに限る。

許可ドメインの制約は稼働するアプリへのアクセス制御であり、MITソースの利用資格ではない。
元のMITと第三者ライセンスを保持し、導入先が自身のWorkspaceに設定できる構成を維持する。
UIの多言語化と辞書データの言語は独立したままとする。

## 公開前の検査

`.env`、認証秘密、SQLiteの本体・WAL等、非公開値の検査リストをGit/Dockerから除外する。
ignoreだけに依存せず、公開検査でも実行時データを拒否する。

非公開にしたいドメイン等は、リポジトリ外のUTF-8ファイルに1行1値で指定できる。
値そのものを公開ポリシーやCIのソースへ記述しない。
次の環境変数は、その**非公開ファイルへのパス**を表す。

```sh
python scripts/check_publication.py --git-ref HEAD \
  --private-values-file "$DEPLOYMENT_PRIVATE_VALUES_FILE"
```

検査リストは最大64KiB、128値、1値4,096文字まで。空のリストや不正形式は拒否する。
指定値を大文字小文字を区別せず検索し、ファイル名・内容・ZIP内の内容も対象にする。
検出時は値をログへ出さず、値を含むパスも伏せる。通常の秘密情報・実データ検査は継続する。
リスト未指定の通常CIでは、その環境固有の値を知り得ないため、公開前に非公開リストを使う。
任意の暗号化・符号化・データフロー全体の解析や、未知の秘密の完全検出を保証するものではない。

## Git履歴の扱い

現行ファイルからの削除は、過去コミット・既存PR本文・既存Dockerイメージからの削除ではない。
P1の共有済み計画書と、公開前のP2コミットに運用ドメインの記載があったため、
今回の修正では現行ファイルから除去した。共有済みmainの履歴や既存PRは書き換えていない。
P2をpushする前には新規コミット履歴も点検し、現行ツリーだけの検査で公開可としない。
履歴の整理が必要な場合は、共有済み履歴への影響を含めて別途対応する。
2026-10-26、P2追加コミットから非公開値を除去した。独立した公開用ブランチも一度作ったが、
ユーザーの指示により削除し、main派生の実装ブランチから通常PRを作成する方針へ統一した。
公開済みmainを継承することと、新しい機密情報を追加することを区別する。
詳細な検査範囲と公開方針は [公開・PRの記録](publication-history.md) を参照する。

この文書は設定・公開方針であり、実装済みP2の本番設定・配備の確認を意味しない。
現在の接続状況は [P2検証記録](p2-verification.md) を参照する。
