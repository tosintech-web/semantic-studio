# P2の履歴整理と公開用ブランチ

2026-10-26、公開前の履歴整理の指示に従い、未公開のP2履歴を整理した。
共有済みmain・リモート・元の作業領域の変更には触れていない。

| ブランチ | 用途 | 履歴の範囲 |
| --- | --- | --- |
| `feat/p2-team-workspace` | 開発継続・既存mainとの比較 | P2固有の履歴を1コミットへ統合。親である共有mainの旧履歴は残る |
| `publish/p2-clean-history` | 既存GitHubへ送る公開用ソーススナップショット | 最初は親なしの1コミット。旧main・旧P2のコミットを引き継がない |

公開時には両ブランチのファイル内容が同一であることを確認する。履歴整理自体はアプリ実装・試験・ライセンス原文を変更しない。
元作者のMIT・著作権表示・第三者通知は維持する。
履歴整理前のP2は、通常のブランチ・タグではないローカル専用のバックアップrefに保持する。
このバックアップは公開対象ではない。共有mainの履歴は変更しない。

## 公開時の選択

実ドメインを過去履歴にも含めたくない公開先には、`publish/p2-clean-history` を使う。
`feat/p2-team-workspace` は共有mainの履歴を継承しているため、同じ条件ではそのまま公開しない。
リポジトリ全体やバックアップを一括送信せず、検査した公開用ブランチだけを送信対象にする。

既存GitHubリポジトリのmainや既存PRに残る記載は、このローカルの整理では消えない。
新しい公開リポジトリへ検査済みのスナップショットを取り込む方法と、
既存の共有履歴の変更は別の操作である。後者は共同作業への影響を含めて別途対応する。
公開用ブランチは既存mainと共通祖先がないため、既存リポジトリへの通常のPR用には使わない。

ユーザーは既存の `tosintech-web/semantic-studio` へ公開用ブランチをpushする方針を選択した。
P2統合後のソースでスナップショットを更新し、送信前に全blobとmetadataを再検査する。
通常PRを作らず、`publish/**` のpushでCIを実行する。以後の修正も検査済みの公開履歴のみを親にする。
実装・検証の範囲と本番Google loginの未確認事項は [P2検証記録](p2-verification.md) を参照する。

## 確認方法

公開用ブランチの全ファイル・コミットメッセージ・著者/コミッター情報を、
リポジトリ外から指定した非公開値で検査する。検査値をログや公開ポリシーへ書かない。
通常の秘密情報・実データ検査も併用し、コピーしたソースとライセンス原文の一致を確認する。
履歴整理の記録・設定方針への参照・公開手順の文書更新を除き、整理前とのGit treeの差分がないことを確認する。

```sh
python scripts/check_publication.py --git-ref publish/p2-clean-history \
  --private-values-file "$DEPLOYMENT_PRIVATE_VALUES_FILE"
```

その検査結果は「選択した公開用履歴が指定した検査を通った」ことを意味し、
旧リポジトリやバックアップから情報を消去したという保証ではない。
