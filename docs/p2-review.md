# P2の実装レビューと修正

2026-10-26、承認済みP2計画の全変更と、指摘に対する修正を独立した担当者が確認しました。
通常のコード・セキュリティレビューです。ホスト型Codex Securityスキャンや、本番環境の
侵入試験を実施したという意味ではありません。検証結果は[P2検証記録](p2-verification.md)へ集約します。

## 全体レビューで確認した指摘

| 指摘 | 影響 | 修正と再現試験 |
| --- | --- | --- |
| 閲覧者の画面と計算権限の不一致 | Shapes検証へ進めず、一部の編集操作が有効に見える | 読取用のEdit・Shapesを用意し、編集・作成と計算操作を分離。Homeから開き、閲覧者が推論・Validateを実行する試験を追加 |
| 権限変更後のUndo/Redo | 管理者時代の削除の逆操作を、降格後の編集者が実行できる | 現在の権限で元操作と逆操作の効果を再認可。snapshot削除・復元、再帰的なUndo/Redoと監査不変を試験 |
| 選択式の未送信入力 | select・checkbox等だけの変更を、定期読取が上書きできる | SHACL・OWL・属性・例データ・作成・データウィザードの未適用入力を所有者単位で追跡。完了・取消後は解放し、権限低下時もフォームを保持 |
| メンバー操作と辞書の版の混同 | 権限変更の後、次の通常編集が不要な競合になる | 利用者の期待版を個別要求だけに使用。管理操作の成功で辞書の編集基準を進めず、同時の辞書更新は引き続き409にする |
| ローカル版の起動判定不足 | APIは動作するが、フロントの初期画面が開かない | ローカル専用のauth/status読取を追加。チーム認証は起動せず、データ・原文を変更しないことと実ブラウザの従来操作を検証 |
| Windowsで意味が変わるファイルキー | POSIXで移行したdrive形式の名前が、別ドライブの候補領域から外れる | drive・代替streamの構文を拒否し、移行前と現在・過去のバックアップ参照も検査。公開前に拒否し、元データと保存先を保持 |

このほか、構成要素のレビューで次の不具合を修正しました。

- 移行CLIの指定外ライブラリへの接触、保存済みJSON-LD contextの再取得、元領域内の移行先、引数エラーへの非公開パスの混入。
- pollingによる無操作期限の延長、Aboutの配布通知への到達不能、ブラウザと異なるOrigin表記、停止時の候補キャッシュの解放漏れ。
- multipart境界の正規化による要求識別の衝突、保存クエリの任意JSONを文書状態と誤認する処理、管理要求と辞書要求のrequest IDの重複。
- native inputのcapture処理がtargetのonChangeより先に再描画する入力巻き戻り。Chromeではmicrotaskでも不十分なため、次のtaskで表示状態を更新。
- 失効・競合中に残るモーダルのキー処理、未送信入力があるログアウト、role低下によるフォームの破棄、認証callback失敗の表示。
- Canvasの保存待ち・実行中の配置とQueryの未保存内容を、対象・セッション単位で保持。競合確認後の再試行は最新配置へ自分の未送信変更だけを重ね、他者の配置を保持。
- 遅延した旧セッションの401と古い版情報による状態の巻き戻り。認証epochと単調な版の検査を追加。
- 日本語・emojiを含むファイルキーのHTTP header。版情報をASCII JSONで送り、Unicodeの意味を保持。
- 書式保存前の共有編集がZIP出力・複製へ反映されない問題。現在の型付きRDFを独立cloneから出力し、元の原文も衝突しない別entryに保持。読取出力がDB・監査・版を変更しないことを検証。
- SQLite writer待ちがイベントループを止める認証処理。threadpoolへ移し、実際のtransaction取得後に時計を読むことで、並行認証の時計逆転による誤失効も防止。

## 検証と範囲

再現試験が失敗することを確認してから修正し、関連試験と再レビューを行いました。
実ブラウザでは合成Google署名・HTTPS・独立cookieの2利用者を使用し、本番の秘密や
実データは使用しません。署名・claim・state等の否定試験は認証APIの試験でも検証します。

sourceだけでは保証できないIME、Tab、AX、WebGL、401復帰、競合レビューはChromeで確認します。
SQLite・blob障害、要求再送、2接続競合、再起動、backup/restoreは実際の一時領域で試験します。
本番Googleクライアント・TLS終端・運用proxyログは別の配備確認であり、確認済みとは扱いません。

2026-10-26の最終独立レビューでは、上の全指摘の解消と追加修正を確認し、
Critical・Important・Minorのいずれにも残る具体的な修正指摘はありませんでした。
認証・認可・CSRF/Origin・漏洩・ファイル境界・SQL/再送/監査・外向き通信・保守の
静的セキュリティレビューも修正不要判定です。レビューは最終全体試験や本番Google確認を代替しません。

GitHubのWindows試験で、追加したZIP原文テストのLF固定の期待値を検出しました。
保存済みCRLFを正しく保持する製品動作は変えず、初回Saveの全文内容を確認した上で、
LF/CRLFそれぞれの不変blobを全OSで明示的に検証するようテストを強化しました。
旧期待値のままではLinuxでもCRLFの3ケースが失敗し、修正後は成功することを確認。
この追加差分の独立再レビューにも修正指摘はありません。

## 実装上の判断

- 初期構成は単一プロセス・ローカルディスクのSQLite。共有領域の版を保守的に検査するため、無関係な更新でも競合・Undo拒否となる場合があります。
- 既存mainの履歴を公開用refへ継承しません。新しい公開用スナップショットだけを既存GitHubへ送るため、mainとの通常PRや履歴の上書きは行いません。
- 独立した新規モジュールのみを担当分離し、共通ファイルの接続とGit操作を統合担当が管理しました。
- 実HTTPS・署名検証のため、配布対象外のtest fixtureとブラウザdriverを追加しました。公開アプリへ試験用認証の例外経路は追加しません。
- drive・streamとして解釈されるopaqueファイル名は、そのまま保持する代わりに移行を拒否します。運用担当が元ファイルを別名へ整理する必要があります。
