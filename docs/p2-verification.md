## 検証済みの動作

- 同じ期待版からの更新を別DB接続で競合させ、1件だけを確定する。
- データと監査の途中や重複要求の保存時にSQLiteの障害を注入し、部分更新を残さない。
- 削除した資源の版番号を墓標に残し、削除・再作成の間の更新を見逃さない。
- 空白ノードのID、literalのlexical値/型/言語、未知の述語、namespaceを往復で保持する。
  rdflibで保持できない重複namespace aliasは黙って落とさず拒否する。
- 初回ログインだけで管理者にしない。明示したGoogle subでのみ初期権限を作る。
  メール変更で別アカウントにせず、降格後の再ログインで再昇格させない。
- 60分の絶対期限、30分の無操作期限、5分のログイン試行期限を境界値で検証する。
- stateをブラウザに紐付けて1回だけ消費する。セッション値はハッシュで保存する。
- 停止・降格を各認証要求に反映し、再有効化で以前のセッションを復活させない。
- 並行する管理者の降格でも、最後の有効管理者を失わない。
- ローカルで生成するRSA鍵の合成ID tokenで実際のGoogle公式検証ライブラリを通す。
  不正署名/aud/iss/exp/iat/hd/email_verified/nonce等を拒否する。
- 認証の外向き通信は固定HTTPS endpoint、既存のアドレス判定と接続先固定、
  offlineと管理者のブロックに従う。redirectを追わず、秘密入りのbodyをログへ残さない。
- DNS解決が時間予算を消費した場合は接続を開始しない。
  同期DNS解決自体を強制終了する仕組みとはしていない。
- 認証ルートfactoryはCookieのSecure/HttpOnly/SameSite/Path、Origin/header/CSRF、
  stateの再利用拒否、Cache-Control、固定リダイレクト、失敗の秘密なし監査を検証済み。

## 独立レビュー

設定/RDF/repository/認証保存層、Google検証と通信、認証ルート、公開検査を別の作者が確認した。
見つかった以下の問題には再現試験を追加し、失敗から成功への変化を確認した。

1. 不整合な認証DBを初期化時に受理し、部分的にtableを追加する問題。
2. 正本DBの主キー・制約・索引の不整合を見逃す問題。
3. 不正な公開Originと、namespace aliasの黙った欠落。
4. 認証におけるDNS後の時間予算のリセット。
5. 失敗した認証の監査記録不足。
6. Python公開検査の展開引数・f-string書式指定による見落とし。

修正対象ごとに再レビューする。P2全体の最終レビュー、ブラウザ2利用者の受け入れ、
GitHubの必須CIは統合完了後に行う。

`docs/team-configuration-privacy.md` に記載する。
