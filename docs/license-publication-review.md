# 改変版のGitHub公開に向けたライセンス確認

確認日：2026-10-24。リポジトリ内の実ファイルと下記の一次資料を確認した技術的な整理。
すべての権利関係を確定する法律意見や、依存物すべてのライセンス監査ではない。

対応計画：`docs/superpowers/plans/2026-10-24-license-publication.md`。
ユーザーの追加条件：ライセンス対応を開発に含め、実データ・認証秘密情報をGitHubで公開しない。
改変版本体にはMITを推奨するが、第三者のライセンスを一括してMITへ変更する意味ではない。

## 結論と確認範囲

アプリ本体の `LICENSE` はMIT、著作権表示は `Copyright (c) 2026 Imran Khan`。
その条件を守って日本語化・機能追加を行い、改変版をGitHubのpublicリポジトリで
公開することは許されている。MITで許された改変・再配布について、通常は元作者の
個別の許可取得を前提にしない。

ただし、アプリのMITはデータ、依存ライブラリ、商標、第三者の創作物まで一括して
許諾するものではない。公開可否は対象ファイル・配布物ごとに確認する。

今回確認したもの：LICENSE、README、About画面、フロントのpackage-lockのライセンス情報、
Pythonの直接依存一覧、同梱語彙のNOTICE/manifest、WordNetサンプルのライセンス、
同梱例のヘッダー、Git追跡対象とtest_dataに関する限定的な履歴確認。
実際のPython推移依存の解決結果・全パッケージの原文・全Git履歴の秘密情報までは未監査。

## アプリ本体と改変部分

- 元の著作権表示とMIT全文（免責を含む）を維持する。元作者名を改変者名に置き換えない。
- 改変部分の権利者は、雇用・委託契約等を含む実際の権利帰属に基づいて表示する。
  GitHubアカウント名や認証用ドメインだけから権利者を決めない。
- 改変部分もMITで公開する方針を推奨する。MITは同一ライセンスでの公開や、
  ソース公開、変更点の開示を強制するライセンスではないが、今回は利用者の公開方針に合う。
- READMEに上流リポジトリへのリンクと、非公式の改変版であること、日本語化・追加機能の
  概要、保守/問い合わせ先を記す。MIT上の必須条件と、この透明性のための推奨を区別する。
- UI上に著作者名を常時表示すること自体はMITの一般的な条件ではない。
  Aboutの元作者クレジットを残し、改変版の提供者を別記する構成が扱いやすい。
  現在Aboutは元作者のリポジトリ・作者名を固定しており、リンク・テストも併せて調整する。
- MITでソースを公開しても、稼働中の編集アプリをWorkspaceメンバー限定にすることは両立する。
  公開ソースの利用者まで `osintech.net` のメンバーに限定する追加条件をMITへ書き加えない。
  許可ドメインはインストールごとの設定として扱う。

## データ・依存物ごとの扱い

| 対象 | 確認結果 | 公開時の扱い |
| --- | --- | --- |
| アプリ本体 | MIT | 元のLICENSEと著作権表示を保持 |
| 日本語WordNetサンプル | 日本語WordNetとPrinceton WordNetの別ライセンス | 両方の全文・出典をデータとともに維持。MITデータと表記しない |
| 同梱標準語彙11件 | NOTICEにCC BY、W3C、PDDL等を記載 | 各ファイルと適用条件を再確認し、通知・原文を維持 |
| 宇宙/物語の同梱例 | ファイル内にCC BY 4.0の表示 | ソフト本体のMITとの適用範囲をREADME等で区別。変更時は変更表示 |
| タグExcel・組織JSONとその変換結果 | 添付から再配布の権利関係を確認できない | ユーザーの指定に従いpublic公開対象から除外。権利確認だけで公開可にしない |
| npm/Python依存物 | 複数ライセンス | 実際に配布する版・依存物の原文/NOTICEを確認し、必要な通知を同梱 |
| ロゴ・名称・Googleブランド | 著作権許諾と商標・表示ルールは別 | 元作者/Googleの公式製品や推薦と誤解させない表示にする |

日本語WordNet/Princeton WordNetには、著作権・条件・免責の保持に加え、
提供機関名の広告・宣伝利用に関する制限がある。事実としての出典表示と、推薦を示す広告を
混同しない。抽出、RDF化、日本語化をしても元データの条件が消えるわけではない。
WordNetの元サイトへのクレジットリンクも保持する。

`backend/app/vocab/NOTICE.md` は有用だが、表に許諾名があるだけで全配布要件を
満たすとは断定しない。特にCC BYではクレジット・ライセンスへのリンク・変更の表示を確認する。
W3C文書ライセンスのファイルを翻訳/改変して再配布する場合は、MITと同様の改変許諾と
決めつけず適用条件を確認する。初期実装では同梱原本を変更せずUI側に説明を持つ。

`backend/app/examples/middle-earth.ttl` は第三者の物語の名称・関係を扱う。
独自記述・非公式という説明とCC BY表示はあるが、それだけで第三者のあらゆる権利を
処分できるわけではない。違法と断定する根拠はないが、初期公開のデモは権利を説明できる
独自の合成データとWordNetサンプルを中心にする案を推奨する。
他の同梱例を残すかは別途確認し、無断で自動削除しない。

## 公開前に実装・確認する項目

1. 原LICENSEを保持し、改変者の帰属を確定。READMEにMITの対象とデータの例外を記す。
2. THIRD_PARTY_NOTICES等に同梱物・依存物の対象版、出典、ライセンス原文/NOTICEを整理。
   配布するDockerイメージ、フロントのビルド、文書ZIPにも必要な通知が渡るか確認する。
3. 原作者・上流と改変版の連絡先を区別する。名称・ロゴの採用は商標等の確認と別の判断にする。
4. 組織/タグの実データ、内部コメント、raw JSON、利用者情報、OAuth秘密情報を
   公開コードから分離。CIのテストは合成データで動かす。
5. .gitignoreだけでなく、既に追跡されたファイル、Git履歴、Release添付、Dockerのbuild context、
   スクリーンショット、ログ、文書出力も公開対象として確認する。
6. Googleのログインボタン等のブランド要件をP2実装時に確認する。商標・ロゴの許可と
   ライブラリのOSSライセンスは別に確認する。

これらは公開前の確認条件であり、現時点でpublic化やpushを実行したという意味ではない。
組織サンプルはgit対象外の `test_data/` で内部検証に使えるが、P1の通常CIには依存させない。
実データ公開を将来検討する場合は、権利確認に加えてユーザーによる公開範囲の変更が必要。
